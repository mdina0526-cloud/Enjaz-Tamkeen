# نظام إدارة المبيعات والموظفين والعمليات المالية

نظام ويب متكامل (React + ASP.NET Core + PostgreSQL) لإدارة طلبات المبيعات، حسابات الموظفين وصلاحياتهم، نسب الاستقطاع، الإيجارات، التقارير المالية، وسجل التدقيق — بواجهة عربية RTL كاملة مع الوضع الداكن والفاتح.

```
frontend/   React 19 + TypeScript + Vite + Tailwind v4 + shadcn/ui + TanStack Query + Recharts + RHF/Zod
backend/    ASP.NET Core 10 Web API + EF Core 10 + PostgreSQL (Npgsql) + JWT + Swagger
  src/SalesSystem.Api/      الخادم (Domain, Data, Services, Controllers)
  tests/SalesSystem.Tests/  اختبارات وحدة وتكامل (xUnit)
docs/       توثيق البنية والواجهات البرمجية وسكربت قاعدة البيانات
```

## التشغيل المحلي

يجب تشغيل الخادم والواجهة معاً؛ تشغيل الواجهة وحدها يُظهر صفحة الدخول، لكن طلب `/api/auth/login` يفشل لأن وكيل Vite يرسل الطلب إلى `http://localhost:5224`. للتشغيل السريع بدون PostgreSQL، افتح نافذتي PowerShell:

```powershell
# النافذة الأولى
cd backend\src\SalesSystem.Api
dotnet run --launch-profile sqlite
```

```powershell
# النافذة الثانية
cd frontend
npm run dev
```

انتظر ظهور `Now listening on: http://localhost:5224` قبل تسجيل الدخول. عند إنشاء قاعدة SQLite لأول مرة، تظهر كلمة مرور حساب `admin` المؤقتة في سجل الخادم؛ احتفظ بها وغيّرها بعد الدخول. في التشغيل باستخدام PostgreSQL استخدم ملف التعريف `http` بدلاً من `sqlite` بعد إعداد قاعدة البيانات كما هو موضح أدناه.

لإنشاء حساب موظف جديد من PowerShell بعد تشغيل الخادم:

```powershell
.\create-employee.ps1 -FullName 'أحمد محمد' -Username 'ahmed'
```

يطلب السكربت كلمة مرور المدير وكلمة مرور الحساب الجديد، ثم يطبع اسم المستخدم والرابط الشخصي. يمكن إضافة `-Email` و`-Phone` و`-JobTitle` و`-DeductionPercentage`، أو تغيير `-ApiBaseUrl` و`-SiteBaseUrl` إذا كان التشغيل على عناوين أخرى. يحتاج حساب مدير صالح؛ كلمة مرور المدير المحددة في `Seed:AdminPassword` لا تغيّر كلمة مرور مدير موجود مسبقاً.

> **ملاحظة Windows:** اسم المجلد يحتوي على `&`، وهذا يكسر ملفات `.cmd` التي يولدها npm. لذلك تستدعي سكربتات `package.json` أدوات Vite وTypeScript وESLint عبر `node` مباشرة، فتعمل `npm run dev/build/lint` بشكل طبيعي. إذا لم يكن `dotnet` في PATH فشغّله بمساره الكامل (مثل `%USERPROFILE%\.dotnet\dotnet.exe`).

### 1) قاعدة البيانات (PostgreSQL)

ثبّت PostgreSQL ثم أنشئ مستخدماً وقاعدة بيانات خاصة بالنظام (من `psql` بحساب `postgres`):

```sql
CREATE ROLE sales_app LOGIN PASSWORD '<كلمة مرور قوية>';
CREATE DATABASE sales_system OWNER sales_app ENCODING 'UTF8';
```

لا يحتاج `sales_app` صلاحيات مدير؛ يكفي أنه مالك قاعدة `sales_system` لتُنشأ الجداول عبر الـ Migrations.

### 2) الخادم

```bash
cd backend
dotnet tool restore                                   # يثبت dotnet-ef محلياً

# الأسرار لا تُحفظ في الكود — تُضبط عبر user-secrets (تطوير) أو متغيرات البيئة (إنتاج)
cd src/SalesSystem.Api
dotnet user-secrets init
dotnet user-secrets set "Jwt:Key" "<مفتاح عشوائي لا يقل عن 32 حرفاً>"
dotnet user-secrets set "Seed:AdminPassword" "<كلمة مرور المدير الأولى>"
# كلمة مرور قاعدة البيانات لا تُكتب في appsettings.json:
dotnet user-secrets set "ConnectionStrings:Default" "Host=localhost;Port=5432;Database=sales_system;Username=sales_app;Password=<كلمة المرور>"

dotnet run --launch-profile http                      # http://localhost:5224
```

- تُطبَّق الـ Migrations تلقائياً عند التشغيل (`Database:ApplyMigrationsOnStartup`). يدوياً: `dotnet ef database update -p src/SalesSystem.Api` من مجلد `backend`.
- يُنشأ حساب المدير `admin` تلقائياً عند أول تشغيل بكلمة المرور المحددة في `Seed:AdminPassword`. إن لم تُحدَّد في بيئة التطوير تُولَّد كلمة مرور عشوائية وتُطبع مرة واحدة في سجل الخادم.
- Swagger: http://localhost:5224/swagger (في بيئة التطوير).
- سكربت SQL كامل لـ PostgreSQL وقابل لإعادة التشغيل: [docs/database-schema.sql](docs/database-schema.sql) (بديل عن التطبيق التلقائي: `psql -U sales_app -d sales_system -f docs/database-schema.sql`).
- القيم المالية `numeric(18,2)`، والأوقات `timestamp with time zone` بتوقيت UTC، والتواريخ التجارية `date`.
- أسماء المستخدمين والبريد تُحفظ بأحرف صغيرة، فالدخول لا يتأثر بحالة الأحرف.

### 3) الواجهة

```bash
cd frontend
npm install
npm run dev                                           # http://localhost:5173
```

يمرّر خادم Vite طلبات `/api` إلى `http://localhost:5224`، فلا حاجة لإعداد CORS أثناء التطوير. للإنتاج انسخ `frontend/.env.example` إلى `.env` واضبط `VITE_API_BASE_URL`، ثم `npm run build`.

### تجربة سريعة بدون PostgreSQL (SQLite)

```powershell
cd backend\src\SalesSystem.Api
$env:Seed__AdminPassword="<كلمة مرور قوية للمدير>"   # تُستخدم مرة واحدة عند إنشاء حساب المدير
dotnet run --launch-profile sqlite
```

ينشئ ملف `App_Data/sales.db` بحساب المدير فقط وبدون بيانات تجريبية. هذا الوضع للتجربة على جهاز واحد وللاختبارات الآلية فقط؛ **قاعدة البيانات المعتمدة للنظام هي PostgreSQL** (SQLite لا يدعم النوع العشري فيخزن المبالغ كأعداد حقيقية).

## صفحة دخول مستقلة لكل موظف

عند إنشاء موظف يُولَّد له رابط دخول خاص بالشكل `http://<النطاق>/e/<رمز عشوائي>`، ويظهر في صفحة الموظف مع زري النسخ والفتح:

- تعرض الصفحة اسم الموظف ومسماه، وتطلب كلمة المرور فقط.
- لا يقبل الخادم عبر هذا الرابط إلا حساب صاحبه؛ أي حساب آخر (حتى المدير) يُرفض.
- "رابط جديد" يُبطل الرابط القديم فوراً، وتعطيل الحساب يوقف الصفحة.
- عند تسجيل الخروج يعود الموظف إلى صفحته الخاصة. صفحة `/login` العامة تبقى متاحة للمدير.

يُنشأ رابط تلقائياً عند التشغيل لأي موظف قديم لا يملك رابطاً.

## قواعد مالية أساسية

- **الاستقطاع** = `round(المبلغ × النسبة ÷ 100, 2)` (تقريب بعيداً عن الصفر). مثال: 1,000 بنسبة 5% → استقطاع 50 والصافي 950.
- تُحفظ النسبة والقيمة **وقت إنشاء الطلب** (في `SalesOrders` و`DeductionRecords`)؛ تعديل نسبة الموظف لاحقاً لا يغيّر الطلبات السابقة، ويُحفظ سجل كامل لتغييرات النسب.
- **طريقة التطبيق قابلة للضبط** من الإعدادات: "يُطرح من الصافي" أو "للتسجيل فقط"، مع مسمى حر (استقطاع / عمولة / رسوم...) وإمكانية التعطيل.
- الحفظ داخل **Transaction** واحدة (الطلب + البنود + الدفعة + سجل الاستقطاع + سجل التدقيق).
- **منع التكرار**: ترسل الواجهة ترويسة `Idempotency-Key` لكل نموذج؛ إعادة إرسال الطلب نفسه تُرجع الطلب الأصلي، مع فهرس فريد يمنع أكثر من دفعة فعّالة لكل طلب.
- **لا حذف للسجلات المالية**: الإلغاء يغيّر الحالة ويُلغي الدفعة مع ذكر السبب، ويُسجَّل في سجل النشاط.

## ما يحتاج إعداداً خارجياً

1. **PostgreSQL**: اختُبر النظام على PostgreSQL 17 فعلي بمستخدم غير مدير (`sales_app`): طُبِّق الـ Migration، ونجحت جميع الوظائف (الدخول، روابط الموظفين، الطلبات المتزامنة وعدم التكرار، الاستقطاعات العشرية، الإلغاء والاعتماد، اللوحات، الفرز والفلاتر، الإيجارات مع المرفقات، التقارير التسعة بصيغ JSON وExcel وPDF)، وبقيت البيانات بعد إعادة التشغيل. يلزمك فقط تثبيت PostgreSQL على جهازك أو خادمك واتباع خطوات الإعداد أعلاه.
2. **الأسرار**: `Jwt:Key` و`Seed:AdminPassword` وسلسلة الاتصال تُضبط عبر user-secrets أو متغيرات البيئة (`Jwt__Key`، `Seed__AdminPassword`، `ConnectionStrings__Default`). في بيئة الإنتاج يرفض الخادم التشغيل دون `Jwt:Key`.
3. **HTTPS والنشر**: يفعّل الخادم HSTS وتحويل HTTPS خارج بيئة التطوير؛ اضبط `App:CorsOrigins` على نطاق الواجهة.
4. **QuestPDF**: مضبوطة على رخصة Community (مجانية للشركات التي تقل إيراداتها عن مليون دولار سنوياً). راجع شروط الرخصة.
5. **المرفقات**: تُحفظ في `App_Data/uploads` خارج مجلد الويب (`Storage:UploadsPath`). خصّص مساراً دائماً ونسخاً احتياطياً في الإنتاج.

مزيد من التفاصيل: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
